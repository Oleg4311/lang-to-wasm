# lang-to-wasm

Компилятор маленького языка **Fox** в WebAssembly. Написан на TypeScript **без единой библиотеки в рантайме**: лексер, парсер, проверка типов, оптимизатор и даже бинарный кодировщик модуля (LEB128, секции, инструкции) — всё своё. Скомпилированный модуль выполняет сам движок WebAssembly.

**Демо:** https://oleg4311.github.io/lang-to-wasm/ — компиляция и запуск прямо в браузере, с выводом сгенерированных инструкций и скачиванием `.wasm`.

```
fn fib(n: int) -> int {
  if n < 2 { return n; }
  return fib(n - 1) + fib(n - 2);
}

fn main() -> int {
  let i = 0;
  while i < 10 { print(fib(i)); i = i + 1; }
  return fib(25);
}
```

```
node src/cli.ts run examples/fib.fox        # скомпилировать и выполнить
node src/cli.ts wat examples/primes.fox     # показать инструкции
node src/cli.ts build examples/fib.fox -o fib.wasm
node src/cli.ts interp examples/fib.fox     # выполнить эталонным интерпретатором
```

Нужен Node.js 24 или новее (TypeScript исполняется напрямую, без сборки).

## Язык

* Типы: `int` — знаковое 64-битное (арифметика по модулю 2⁶⁴, как `i64` в WebAssembly) и `bool`.
* Функции с параметрами и результатом, рекурсия, взаимная рекурсия (порядок объявления не важен). Точка входа — `fn main() -> int`.
* `let`, присваивание, `if` / `else if` / `else`, `while`, `break`, `continue`, `return`. Блоки образуют области видимости, внутренний `let` может затенять внешний.
* Операторы: `+ - * / %` (деление и остаток усекаются к нулю), сравнения, `== !=` для `int` и `bool`, `!`, унарный `-`, ленивые `&&` и `||`.
* Встроенная `print(x: int) -> int` печатает число и возвращает его же.
* Деление на ноль и `MIN / -1` — ловушка (как в WebAssembly); `MIN % -1` равно нулю. Аргументы вычисляются слева направо.
* Ошибки компиляции всегда с позицией `строка:столбец` и понятным текстом: неизвестное имя, неверные типы, `break` вне цикла, недостижимый код, функция, которая может завершиться без `return`, и т. д.

## Как устроено

```
текст ─► лексер ─► парсер ─► проверка типов ─► оптимизатор (AST) ─► генерация ─► кодировщик ─► .wasm
                                   └──► эталонный интерпретатор (для сверки)
```

* **Генерация.** `int` → `i64`, `bool` → `i32`; каждая переменная получает свой локальный слот. `while` превращается в `block { loop { условие; br_if выход; тело; br повтор } }`, `break` и `continue` — переходы `br` на нужную метку (глубина считается по стеку меток). `&&` и `||` — условные выражения `if (result i32)`, поэтому правая часть вычисляется лениво.
* **Кодировщик.** Знаковый и беззнаковый LEB128 (в том числе полные 64 бита), типы функций без дублей, импорт `env.print`, группировка локальных переменных, секции в правильном порядке. После каждой функции вставляется `unreachable`: проверка типов гарантирует `return` на всех путях, но валидатору WebAssembly это нужно сказать явно.
* **Оптимизатор** (на уровне дерева, до неподвижной точки): свёртка констант с точной семантикой i64; подстановка неизменяемых констант (в том числе удаление их `let`); алгебраические упрощения (`x + 0`, `x * 1`, `x / 1`, `!!x` и т. д.); отбрасывание ветвей с константным условием, `while false`, кода после `return`/`break`/`continue`. Главное правило: поведение не меняется **вообще** — выражение, которое может упасть (деление) или иметь побочный эффект (вызов), никогда не выбрасывается, даже если результат умножается на ноль.
* **Эталонный интерпретатор** — самый простой способ выполнить программу (обход дерева на `BigInt`). Он нужен только для проверки.

## Как проверяется

Всего **76 тестов** на Node (`npm test`) и **18 браузерных сценариев** Playwright (`npm run e2e`): десктоп и телефон, доступность axe в светлой и тёмной теме.

| Что | Как |
|---|---|
| Кодировщик | эталонные векторы LEB128 из спецификации; независимый декодер в тесте; 5000 случайных чисел туда и обратно, проверка минимальности кодирования; границы 64 бит |
| Фронтенд | 37 «плохих» программ: сообщение **и точная позиция** каждой ошибки; патологическая вложенность (50 000 скобок) даёт ошибку компиляции, а не падение |
| 21 эталонная программа | Фибоначчи, Евклид, простые числа, Коллатц, взаимная рекурсия, `break`/`continue` во вложенных циклах, ленивость `&&`/`||`, порядок вычисления аргументов, переполнение, усечение деления, все виды ловушек, глубокая рекурсия — выполняются тремя способами (интерпретатор, код без оптимизации, оптимизированный код) и должны совпасть с ожидаемым значением |
| **Дифференциальный тест** | генератор строит случайные, всегда завершающиеся программы (циклы с счётчиком, вызовы только вперёд, одна рекурсия с базовым случаем); результат, весь вывод и вид ловушки у трёх движков обязаны совпасть. 1500 программ по умолчанию, 4000 в CI (`DIFF_CASES`); около 12% программ заканчиваются ловушкой |
| Оптимизатор | не раздувает код (на 200 программах), реально сокращает, идемпотентен, не выбрасывает вызовы и деления |
| **Мутации** | `npm run mutate` по очереди ломает 18 деталей (метка выхода из цикла, порядок операндов унарного минуса, умножение на ноль с вызовом, свёртка без переполнения, константа в изменяемой переменной, знаковый LEB128, контроль `return`, …) и проверяет, что тесты краснеют; сначала обязателен зелёный базовый прогон и безвредная контрольная мутация. Все 18 пойманы |

**Что нашли сами проверки по ходу работы:** сообщение ловушки остатка в V8 («remainder by zero») отличается от деления — классификатор ловушек его не знал; оптимизатор сходился только за два прохода, а не за один (теперь идёт до неподвижной точки, тест на идемпотентность); генератор поначалу вызывал рекурсивную функцию с произвольным аргументом и порождал бесконечную рекурсию; страница могла зависнуть от `while true`, поэтому выполнение вынесено в Web Worker с ограничением в 3 секунды и 5000 чисел вывода.

## Честные ограничения

* Язык намеренно мал: нет массивов, строк, чисел с плавающей точкой, структур, замыканий, глобальных переменных и памяти WebAssembly.
* Оптимизатор работает на дереве: нет удаления неиспользуемых переменных с побочными эффектами в инициализаторе, встраивания функций, замены умножения на степень двойки сдвигом и анализа живости.
* Классификация ловушек опирается на тексты сообщений V8 (Node, Chrome). В других движках сообщения иные, и `run` может не распознать ловушку.
* Переполнение стека сверяется лишь приблизительно: глубина, при которой оно случается, у интерпретатора и у движка WebAssembly разная; тесты берут для этого явный предел глубины.
* Случайные программы строятся так, чтобы завершаться; бесконечные циклы и тяжёлые вычисления сверяются только на заведомо конечных примерах.
* Демо ограничивает работу 3 секундами и 5000 числами вывода; пользовательская программа выполняется в отдельном потоке, но не в песочнице за пределами того, что даёт сам WebAssembly.

## English

**lang-to-wasm** compiles **Fox**, a tiny statically typed language (64-bit `int`, `bool`, functions, recursion, `while`, `break`/`continue`, lazy `&&`/`||`), to WebAssembly. Everything is hand-written in TypeScript with no runtime dependencies: lexer, parser, type checker, an AST optimizer (constant folding and propagation, branch pruning — never dropping anything that can trap or has side effects), code generator and a binary encoder (LEB128, sections, instructions). A demo runs in the browser: https://oleg4311.github.io/lang-to-wasm/ (execution in a Web Worker with a 3 s limit).

Correctness is checked, not asserted: a separate tree-walking interpreter is the reference, and thousands of random terminating programs must produce identical output, result and trap from the interpreter, the unoptimized module and the optimized module. Also: LEB128 vectors and round-trips, 37 ill-formed programs with exact error positions, 21 reference programs, browser tests with axe, and a mutation script that breaks 18 details of the compiler and optimizer and requires every break to be caught.

Limits: no arrays, strings, floats or globals; trap detection relies on V8 message texts; optimizer is tree-level only; the demo is not a security sandbox beyond what WebAssembly itself provides. Run locally with Node.js 24+: `node src/cli.ts run examples/fib.fox`.
